# 全局可观测性标准

## 文档职责

**架构定位**：观察点的唯一权威契约。

**核心目标**：调查问题时能看到一次执行经过了哪些步骤、每一步的实际状态与数值、结果从哪一步开始
偏离预期——为此规定哪些位置必须被观察、记录的形状与关联字段、观察代码的放置、启停方式、脱敏边界
和交付前的完成门。

**职责边界**：本文只回答“系统运行时应当暴露什么”。观察点的实现分布在生产代码中，本文只定义它们
必须共同满足的约束；实施范围与进度由 [`docs/roadmap.md`](./roadmap.md) 接管。调查方法与调试命令由
[`docs/development.md`](./development.md) 维护，用户可见排障由 [`docs/usage.md`](./usage.md) 维护，
阶段验收门禁由 [`docs/verification.md`](./verification.md) 维护。

## 记录与观察是两件事

两者都产生数据，但架构角色不同；混用会让事实源失去边界。

|          | 记录（record）               | 观察（observe）            |
| -------- | ---------------------------- | -------------------------- |
| 表达什么 | 注入了什么内容——事实的一部分 | 过程如何流转——诊断依据     |
| 承载位置 | Pi JSONL entry，随事件同步   | 独立 JSONL，永不同步       |
| 生命周期 | 与会话事实同寿               | 与一次调查同寿，可随时删除 |
| 默认状态 | 开启                         | 关闭                       |
| 当前载体 | `ov-observation` entry       | 本文定义的观察记录         |

持久 Pi JSONL 保持唯一事实源。观察记录不得被同步到 OpenViking，不得被任何功能读取用于决策；
删除全部观察记录不得改变系统行为。

## 三条不可让渡的约束

标准的形状由“扩展运行在 Pi 进程内”这一定位决定，这三条先于任何便利性：

1. **不影响 Pi 主任务**——观察实现永不抛出、永不阻塞；关闭时零开销。
2. **不承载凭证与会话内容**——由实现层统一保证，不依赖调用点自觉（见“脱敏契约”）。
3. **不引入分布式追踪**——扩展是单进程组件。关联由 `session`、单调 `seq` 与点位自带的
   `entryId`/`uri`/OpenViking `traceId` 表达，不设 trace/span 体系。

## 记录形状与关联字段

单行 JSON，便于 `jq`、`grep` 与计数聚合：

```json
{
  "ts": "2026-08-18T14:31:02.187Z",
  "seq": 42,
  "session": "a1b2c3d4",
  "kind": "boundary",
  "stage": "ov_http",
  "data": {}
}
```

| 字段      | 含义                                                                    |
| --------- | ----------------------------------------------------------------------- |
| `ts`      | ISO-8601 毫秒时间戳                                                     |
| `seq`     | 进程内单调递增序号；并发操作交错时用它恢复因果顺序                      |
| `session` | Pi session id；跨进程关联同一会话的多次运行                             |
| `kind`    | 五类之一：`boundary`、`decision`、`transition`、`checkpoint`、`failure` |
| `stage`   | 点位名，snake_case，模块前缀加动作，如 `ov_http`、`tool_scope_denied`   |
| `data`    | 该点位的结构化数据，受脱敏契约约束                                      |

三个关联字段就是全部关联机制：`session` 定位一次会话，`seq` 定位顺序，`traceId` 把一次失败对齐到
OpenViking 服务端。跨进程的多次运行由 `session` 串起，这正是 Pi 会话可跨进程恢复所需要的粒度。

## 五类观察点

分类由调查时实际提出的问题倒推，而非通用框架的分层。

### `boundary`——跨进程与跨网络的每一次交互

回答“扩展和外部之间到底发生了什么”。

- **覆盖**：`client.ts` 每次 HTTP 进出；`index.ts` 绑定的每个 Pi 生命周期钩子的进入与返回。
- **必带**：方向、method、path、HTTP status、耗时毫秒、OpenViking `traceId`。

`traceId` 是扩展与服务端之间唯一的关联句柄，必须逐条透出，使一次失败可以在两侧对齐。

### `decision`——每个改变后续路径的判断

回答“为什么走了这个分支”。只记录结果不足以支持调查，**输入值与选中分支必须同时出现**。

- **覆盖**：记忆命名空间解析、`viking_*` 工具的边界判定（放行与拒绝都记）、Content capability 判定、
  fail-open 降级、ACK 推进与停止、recall 的来源与降级选择。

### `transition`——长生命周期状态的每次变化

回答“状态什么时候、因为什么变的”。

- **覆盖**：连接状态、`sync.capability`、ACK frontier、`bindUser` 的命名空间绑定。
- **必带**：`from` 与 `to`。

### `checkpoint`——定点状态快照

观察默认关闭，一段记录可能从任意时刻开始，因此不能要求调查者靠重放全部 `transition` 推断当前状态。
checkpoint 让每段记录自解释。

- **定点**：会话开始、每次 `turn_end`、shutdown。**只有这三处**，避免退化成随处快照。
- **必带**：连接状态、绑定命名空间、ACK frontier 规模、待重放 entry 数。

### `failure`——所有被吞掉的异常

fail-open 是产品保证，静默不是。**每一个 `catch` 都必须留痕**，否则降级路径在调查中不可见。

- **覆盖**：生产代码中的每个 `catch` 块。
- **必带**：点位名、error name 与 message、本次是否已降级。

## 覆盖完整性

要求是“每条路径可观察”，但**不另建路径矩阵产物**：`docs/roadmap.md` 的阶段验收与 `test/live/` 的
`successCriteria`/`falsification` 已经在枚举路径，再维护一份矩阵就会产生第二个事实源。

因此覆盖规则表述为对既有来源的约束：

- `AGENTS.md`“必须保持的系统保证”中每一条涉及降级、拒绝或冲突的保证，其触发点必须有 `decision`
  或 `failure` 点位。
- `docs/roadmap.md` 各阶段验收中每条已命名的失败路径，必须能在观察记录中被识别。
- 新增分支时，成功路径与每条降级路径同时获得点位；只覆盖成功路径视为未完成。

## 两种记录去向，一套实现

同一套记录形状与脱敏规则，两种指定去向的方式，对应两类消费者与两种信任模型：

| 去向             | 指定方式             | 消费者               | 为什么需要                                                     |
| ---------------- | -------------------- | -------------------- | -------------------------------------------------------------- |
| 文件路径         | `OV_OBSERVE=<path>`  | 人工与编码代理调查   | 事后可读、可 `jq`、可长期保留                                  |
| 继承的文件描述符 | `OV_OBSERVE_FD=<fd>` | live gate 等自动采集 | Pi 的 stdout 是 RPC 通道、TUI 占用终端；且被观察进程不选择落点 |

FD 方式沿用 `scripts/e2e-probe.ts` 已验证的约束：必须是继承的 3–999 号常规文件描述符，且权限不含
group/other 位。这不只是便利——**被观察的进程不解析、不拥有记录路径**是一条安全属性。

两者不是两套系统：同一实现、同一形状、同一脱敏。两者都未设置时观察关闭。

## 脱敏契约

采用白名单。黑名单的完整性无法验证——总可能漏掉一个字段名，而漏掉一次就是一次凭证或会话内容落盘。

- `data` 只接受显式声明的标量：数值、布尔、枚举、URI、hash、长度、计数。
- 内容一律降为度量：`{"bytes":8392704,"sha256":"a1b2c3d4e5f6"}`，不放正文。
- 实现层对不属于白名单的值统一替换为 `"<omitted:type>"`，该兜底不依赖调用点。

URI 属于允许项：它承载命名空间归属，是边界类调查的必要信息，且不含凭证。

这条契约同时约束热路径开销：既然不放正文，`data` 构造恒为廉价，观察接口因此保持
`observe(kind, stage, data)` 的最简签名，无需惰性求值。

## 代码放置

- 单一实现位于 `shared/observe.mjs`：形状、序号、脱敏、去向解析、启停全部在这里，别处不得重复。
- 观察调用写在**承担该职责的模块内部**，与被观察的判断相邻；不设集中的观察层，也不在调用方外部
  推断被调用方的内部状态。
- 观察调用不得改变控制流：不得作为条件、不得改变返回值、不得引入 `await` 以外的时序依赖。

## 启停与开销

- `OV_OBSERVE` 与 `OV_OBSERVE_FD` 均未设置时完全关闭：实现首行返回，不构造对象、不触碰文件系统。
- 文件去向的权限为 `0600`：记录含会话元数据。
- 与 `logLevel` 严格分离。`logLevel` 控制用户可见的 UI 通知，观察记录面向调查者，二者互不影响。

## 完成门

新增、修改或修复功能时，观察点与功能代码一起设计、一起实现、一起验证。满足以下三条才算完成：

1. 该功能的成功路径与每条降级路径都有点位，分类与必带字段符合本文。
2. 附一次**真实运行**产生的记录片段作为证据，而非仅有代码。
3. `npm test` 中该功能的测试与本文“验证”一节的检查同时通过。

问题调查先读取实际记录；证据不足时，在任务授权边界内补充点位再复现，而不是靠推断继续。

## 唯一性

项目只保留一套观察点体系。发现统一观察点之外的第二套，或名为其他用途但本质是观察点的内容，必须
报告并收敛；收敛后确认没有留下相关代码、文档、配置、测试或运行记录。

与观察点相邻但**职责不同、不并入**的内容：

- `test/live/phase0-live.mjs` 的 `log.check`——记录的是断言的期望值、实际值与通过与否，属于验证器
  产出，不是对系统运行过程的观察。
- `ov-observation` entry——属于事实记录，见“记录与观察是两件事”。

## 验证

标准必须可验证，否则会退化为建议。以下检查是标准的一部分：

| 事实             | 验证方式                                                             |
| ---------------- | -------------------------------------------------------------------- |
| 脱敏契约成立     | 喂入含 API key、Authorization 与会话正文的对象，断言输出不含任何原值 |
| 五类点位覆盖成立 | 执行一次完整同步，断言五类 `kind` 均出现且 `failure` 可定位到源位置  |
| 关闭时零开销     | 两个环境变量均未设置时断言无文件写入                                 |
| 两种去向等价     | 同一次运行分别经路径与 FD 输出，断言记录逐行一致                     |
| 记录不进入事实源 | 断言观察记录不出现在 Pi JSONL 与 OpenViking 事件命名空间中           |

## 实施归属

本文只定义契约。观察点的实施范围、顺序、当前状态和阶段出口由 [`docs/roadmap.md`](./roadmap.md) 统一接管，
与产品阶段同一条实施路径推进。评估某个观察点是否合规时以本文为准；判断它是否已经落地时以
`docs/roadmap.md` 的实施状态为准。
