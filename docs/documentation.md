# 项目文档规范

## 文档职责

**架构定位**：项目长期文档的规划与格式规范。

**核心目标**：维护者能够知道项目规划了哪些文档、每份文档有什么作用，以及文档如何表达和组织自身职责。

**职责边界**：本文维护文档清单、职责格式、路径、命名、引用；每份文档自行维护其架构定位、核心目标、职责边界和具体项目事实。

## 规划文档

仓库根目录的入口文档：

| 路径 | 作用 |
| --- | --- |
| `README.md` | 项目入口与面向消费者的文档导航 |
| `AGENTS.md` | 编码代理的仓库工作指引 |
| `CLAUDE.md` | 指向 `AGENTS.md` 的工具约定入口 |

`docs/` 下的长期文档：

| 路径 | 作用 |
| --- | --- |
| `docs/design.md` | 目标架构与稳定边界的总纲 |
| `docs/documentation.md` | 文档规划与格式规范 |
| `docs/roadmap.md` | 阶段路径、实施状态与下一实施入口 |
| `docs/verification.md` | 证据类型、测试组织与 gate 契约 |
| `docs/usage.md` | 面向最终用户和服务操作者的产品说明 |
| `docs/development.md` | 开发环境、开发循环与清理 |

表中“作用”只用于区分文档入口。每份文档在自己的 `文档职责` 中定义完整目标和边界。尚未建立的文档由
[`docs/roadmap.md`](./roadmap.md) 维护其建立时机。

## 职责格式

`docs/` 下每份文档以 `文档职责` 作为首个二级章节，并在该章节使用三个字段：

- **架构定位**：说明本文在项目文档系统中的存在理由和依赖位置；
- **核心目标**：说明本文长期服务的读者结果；
- **职责边界**：说明本文维护的内容范围以及相邻内容的引用位置。

三个字段是职责表达格式，每份文档依据自身作用维护字段值。

职责之后的章节由当前内容决定。每项内容服务于本文核心目标并保持在职责边界内；同一事实由一份文档完整维护，其他文档通过链接引用。

## 路径与命名

仓库根目录保存由外部工具约定自动发现的入口文档，其结构服从该约定；`docs/` 保存通过项目导航访问的长期文档。

- `docs/` 下目录和 Markdown 文件使用小写名称；
- 多词名称使用连字符；
- 文件名表达文档作用；
- 长期文档使用 `.md` 扩展名。

## 引用

- 文档之间使用相对链接；
- 代码、配置、测试和用户输出使用仓库根相对路径；
- 文件移动时同步更新仓库内路径引用；
- README 连接面向项目消费者的文档入口。

## 新增文档与目录

新文档同时具有：

1. 现有文档无法承担的独立作用；
2. 明确消费者；
3. 独立维护周期；
4. 可执行的验证方式。

新文档先进入 `docs/` 平级空间。多个同类文档实际形成共同导航需求后，再建立对应目录，并在本文规划其作用与职责格式。
